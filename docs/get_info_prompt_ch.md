幫我把 AI 助理的長期脈絡資料整理成可匯入另一個 AI 助理的結構化使用者 Context。

你的工作是瀏覽目前可存取的過去對話、記憶與相關脈絡資料，分析其中反覆出現且具有長期價值的資訊，並建立一份精煉、準確、可供另一個 AI 助理直接使用的使用者 Context。

重要原則：

1. 只能根據實際可存取的對話、記憶與脈絡資料整理，不得虛構、猜測或補充沒有證據支持的資訊。
2. 優先保留具有長期價值的資訊，而不是一次性的閒聊、短期事件或偶然提及。
3. 如果某項資訊只有單次提及，且無法判斷具有長期意義，除非對理解使用者目前狀態非常重要，否則不要納入。
4. 區分「使用者明確表達的資訊」與「從多次對話合理歸納出的模式」。可以進行合理歸納，但不得將推測描述成確定事實。
5. 優先整合跨多次對話反覆出現的資訊。
6. 不要大量複製原始對話；應將資訊濃縮成另一個 AI 助理可以快速理解與使用的 Context。
7. 不要因為某個主題曾經被提及，就直接視為使用者的長期興趣。只有持續關注、反覆討論、實際投入或明確表達喜好的領域，才應列入 interests。
8. active_problems 應描述「目前仍可能需要持續處理或思考的問題、任務與挑戰」，不要把已經明確完成且不再延續的事情列入。
9. recurring_topics 應描述對話中反覆出現的主題，不等同於 interests；可以包含工作、學習、技術問題、專案或經常討論的概念。
10. friend_intent 應描述使用者期待 AI 助理以什麼樣的「朋友／對話夥伴」角色互動，例如技術顧問、思考夥伴、嚴格的批判者、協作者、學習夥伴等。只有有足夠對話證據時才進行歸納。
11. history_scope 必須誠實描述本次分析實際能夠檢查到的歷史資料範圍，以及無法檢查的內容。不得聲稱瀏覽了模型實際無法存取的完整歷史。
12. 不要輸出敏感個人資訊，除非該資訊是完成任務所必要且已有明確授權。
13. 不要使用第一人稱代名詞（我、我的）或第二人稱代名詞（你、你的）。所有內容應以「使用者」或中性第三人稱描述。
14. 如果沒有足夠資訊支持某個欄位，使用空字串 "" 或空陣列 []，不要猜測。
15. 輸出必須是合法 JSON，不得加入 Markdown、```json、註解、開場白、結尾語或任何 JSON 以外的文字。

請依照以下 Schema 輸出：

{
  "summary": "一句話精煉使用者的人格特質、背景或核心定位",
  "interests": [
    "使用者長期關注、喜好或投入的領域與主題"
  ],
  "motivations": [
    "驅動使用者前進的內在核心驅動力、目標或願景"
  ],
  "active_problems": [
    "使用者目前正在積極應對、思考或試圖解決的痛點、任務或挑戰"
  ],
  "recurring_topics": [
    "對話中頻繁出現、經常被提及的討論焦點"
  ],
  "friend_intent": "使用者期待 AI 助理扮演什麼樣的朋友或對話夥伴，以及偏好的互動方式",
  "history_scope": "本次分析實際可以檢查的歷史資料範圍，以及無法檢查的資料範圍"
}

各欄位要求：

summary：
- 僅使用一句話。
- 濃縮使用者最重要的背景、人格特質、思考方式與核心定位。
- 不要堆砌職業、興趣、專案清單。
- 應讓另一個 AI 助理讀完後立即理解「這是一個什麼樣的使用者」。

interests：
- 列出具有長期性、重複性或明確投入證據的興趣與領域。
- 每個項目應簡潔且具體。
- 不要列出單次購買、偶然提問或一次性的興趣。
- 優先列出技術領域、學習方向、創作／專案方向、產業與長期關注主題。

motivations：
- 描述使用者「為什麼持續做這些事情」。
- 優先從長期目標、價值觀、成就追求、職涯方向、創業動機、學習動機等面向歸納。
- 不要只是重複 interests。

active_problems：
- 只列出目前仍具有延續性的問題、任務或挑戰。
- 可以包含正在開發的專案、技術瓶頸、學習問題、決策問題或尚未完成的目標。
- 已經明確解決且沒有後續脈絡的問題不要列入。

recurring_topics：
- 找出歷史對話中反覆出現的主題。
- 這個欄位著重「經常談什麼」，而 interests 著重「長期關注什麼」。
- 可以列出技術除錯、AI、GitHub Actions、競賽、SaaS、量化交易等反覆出現的討論方向。

friend_intent：
- 描述 AI 助理應如何理解與使用者互動。
- 如果對話顯示使用者偏好直接、具體、少廢話、不要重複已知資訊、直接解決問題等特徵，可以納入。
- 不要把一次性的情緒或單次要求誤認為長期互動偏好。

history_scope：
- 明確說明此次分析涵蓋了哪些可以實際存取的資料。
- 同時說明哪些歷史資料、對話、記憶或帳戶內容無法存取。
- 不得假裝擁有完整且無限制的歷史紀錄。

品質要求：

- 寧可少寫，也不要猜測。
- 優先保留高信心、長期、有助於未來對話的資訊。
- 避免重複。
- 避免空泛描述，例如「喜歡學習新事物」。
- 將具體的多次對話證據整合成高層次但可操作的 Context。
- 最終結果必須可以直接提供給另一個 AI 助理作為使用者背景 Context。

最後只輸出合法 JSON。
